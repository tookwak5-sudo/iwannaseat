# 🪑 워너 싯다운 (Wanna Sitdown)
> ** "단순 혼잡도 조회를 넘어, 목적지까지 앉아갈 확률이 가장 높은 지하철 칸을 추천합니다."**

## 📌 1. 프로젝트 개요 (Overview)
기존 대중교통 앱은 탑승 시점의 단편적인 실시간 혼잡도만 제공합니다.
**워너 싯다운(가제)**은 출발역부터 목적지까지의 **전체 이동 구간 승객 흐름(역별 시간대 승하차 통계)**을 시뮬레이션하여, 목적지에 도착하기 전 좌석을 확보할 가능성이 가장 높은 차량(칸)을 전략적으로 추천하는 1인 풀스택 프로젝트 입니다.


## 💡 2. 핵심 차별점: 왜 '지금 덜 붐비는 칸'이 정답이 아닐까?

| 구분 | 일반 대중교통 앱 | 워너 싯다운 (Wanna Sitdown) |
| :--- | :--- | :--- |
| **제공 정보** | 현재 시점의 차량별 혼잡도 스냅샷 | 출발~도착 구간 누적 착석 기대치 |
| **추천 기준** | "지금 가장 한산한 차량" | "이동 중 좌석이 날 확률이 가장 높은 차량" |
| **고려 요소** | 현재 탑승 인원 | 현재 혼잡도 + 경유역별 대규모 환승/하차 흐름 |

> **핵심 시나리오 비교**:
> 현재 3호차의 혼잡도가 가장 낮더라도, 2호차가 2정거장 뒤 대규모 환승역(교대역 등)에서 승객의 40% 이상이 하차한다면 목적지까지 앉아서 갈 기회는 2호차가 훨씬 높습니다.


## 🧠 3. 착석 추천 알고리즘: 2단계(Tier) 우선순위 전략

전동차 1량의 물리적 정원 기준(혼잡도 100% = 160명, 기본 좌석 수 = 54석)에 따라, **혼잡도 약 34%(54/160)**를 기준으로 알고리즘을 2단계로 분기합니다.
```

                                [사용자 탑승 시점]
                                        │
                 ┌──────────────────────┴──────────────────────┐
                 ▼                                             ▼
        [조건 1: 즉시 착석 가능]                       [조건 2: 모든 칸 만석 (입석)]
      (특정 칸 혼잡도 < 34%)                         (모든 칸 혼잡도 ≥ 34%)
                 │                                             │
                 ▼                                             ▼
         【Tier 1: 즉시 착석】                         【Tier 2: 미래 기회 시뮬레이션】
     • 점수: 90 ~ 100점 (무조건 최우선)               • 탑승 즉시 착석 불가 (입석 경쟁)
     • 추천: 현재 혼잡도가 가장 낮은 칸                • 경유역 하차 승객 흐름 추정
     • 안내: "현재 빈 좌석 여유! 지금 바로 착석 가능" • 점수: 누적 착석 확률 (0 ~ 89점)
                                                       • 안내: "2정거장 뒤 OO역 대규모 하차 예상"

```

### 1) Tier 1: 즉시 착성 (혼잡도 < 34%)
* 탑승 시점에 이미 물리적 빈자리가 존재하는 칸입니다.
* 미래 하차 시뮬레이션을 건너뛰고 해당 칸을 최우선(1위)으로 추천합니다.
* 점수 산식: $\text{Score} = 100 - \text{현재 혼잡도}$ (90~100점 대)

### 2) Tier 2: 미래 기회 시뮬레이션 (모든 칸 혼잡도 ≥ 34%)
* 출퇴근 시간 등 모든 칸에 빈자리가 없어 서서 가야 하는 상황입니다.
* 출발역부터 목적지까지 각 경유역을 통과할 때마다 발생하는 하차자 중 "좌석 이탈 추정치($FreedSeats$)*와 **"서 있는 승객 간 경쟁률($p_k$)"**을 순차 시뮬레이션합니다.
* 목적지까지 한 번이라도 자리가 날 확률(여사건 모델)을 0~89점 사이 점수로 환산합니다.

$$\text{Seat Probability} = 1 - \prod_{k=1}^{n} (1 - p_k)$$

## 🏗️ 4. 시스템 아키텍처 및 데이터 흐름
공공데이터 API의 호출 제한(Rate Limit)과 응답 지연을 방지하기 위해 **"비동기 백그라운드 수집"**과 **"실시간 계산 서비스"**를 완전히 분리했습니다.

```
[외부 공공데이터 API]
  ├── 서울시 실시간 지하철 도착/위치 API ──(1~2분 주기 수집)──► [Spring Boot In-Memory Cache]
  └── 티머니 역별/시간대별 승하차 통계 ────(배치 적재)─────► [Oracle 11g DB]
                                                                     │
[사용자 요청 (출발역 -> 도착역)] ─────────────────────────────────────┴──► [추천 엔진 (Score 연산)]
                                                                             │ (연산 소요시간 < 0.05초)
[응답: 추천 칸, 선정 근거 텍스트, 칸별 점수 DTO] ◄────────────────────────────┘
```

* **서버 부하 최소화**: 사용자가 검색할 때마다 외부 API를 호출하지 않고, 서버 스케줄러가 메모리에 갱신해 둔 최신 데이터를 활용해 초고속(In-Memory) 사칙연산만 수행합니다.

## 🛠️ 5. 기술 스택 (Tech Stack)

### Backend
* **Language / Framework**: Java 17, Spring Boot 3.x
* **Data Access**: Spring Data JPA
* **Database**: Oracle Database 11g Express Edition
* **Caching**: Spring In-Memory Cache (`ConcurrentHashMap`)
* **Build Tool**: Gradle

### Frontend
* **Library / Build**: React 18, Vite
* **Styling**: Tailwind CSS (모바일 우선 반응형 UI)
* **HTTP Client**: Axios
